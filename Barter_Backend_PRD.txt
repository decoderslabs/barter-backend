7. KEY BUSINESS LOGIC
--------------------------------------------------------------------------------

PROPOSAL STATE MACHINE
pending → countered (either party) → accepted → [Deal created]
pending → declined
countered → accepted
countered → declined
countered (round 3, no response after 7 days) → expired

DEAL STATE MACHINE
pending_membership → active (on membership approval)
active → delivered (creator submits)
delivered → revision_requested (brand requests, max 2)
revision_requested → delivered (creator resubmits)
delivered → complete (brand approves, both rate, fee charged)
active/delivered → disputed (either party flags)
disputed → complete / cancelled (admin resolves)

BARTER SCORE CALCULATION (run after each rating)
  score = (avg_star_rating × 0.5)
        + (completion_rate × 0.3)        # completed / accepted deals
        + (on_time_rate × 0.2)           # delivered before deadline
  Normalised to 0–10 scale. Recalculated and saved to User.barter_score.

CREATOR TIER (auto-calculated on OAuth sync)
  max_followers = max across all connected SocialAccount.followers
  nano   = < 10,000
  micro  = 10,000 – 99,999
  mid    = 100,000 – 499,999
  macro  = 500,000 – 999,999
  mega   = 1,000,000+

DEAL FEE CALCULATION
  value = Deal.agreed_terms['offer_estimated_value']
  INR:  <= 5000 → 999 | <= 15000 → 1499 | <= 50000 → 1999 | > 50000 → 2999
  AED:  proportional (1 INR ≈ 0.044 AED)
  USD:  proportional (1 INR ≈ 0.012 USD)
  Fee stored on Deal.deal_fee at deal creation. Never recalculated after.

MEMBERSHIP POINTS → PRO MONTHS
  points_to_months = {50:1, 100:2, 150:3, 250:6, 400:12}
  On approval: add points to total. Find highest milestone crossed.
  pro_expires_at = max(now(), current pro_expires_at) + timedelta(months=earned)
  Carry forward unused points.

PERIOD RESET (cron, runs daily at midnight UTC)
  For each CreatorMembership where period_reset_at <= now():
    clear tasks_this_period
    if tier in [nano, micro]: period_reset_at = first day of next month
    if tier in [mid, macro, mega]: period_reset_at = first day of next quarter

9. OAUTH — SOCIAL ACCOUNT SYNC
--------------------------------------------------------------------------------

Flow for all platforms:
  1. Flutter opens OAuth URL in webview / browser
  2. User authorises → redirect to /api/auth/oauth/{platform}/
     with code in query params
  3. Django exchanges code for access_token
  4. Django calls platform API to pull stats
  5. Saves/updates SocialAccount record
  6. Returns updated creator profile to Flutter

Instagram (Graph API):
  Scopes: instagram_basic, pages_read_engagement
  Pull:   followers_count, media_count
  Engagement: calculate from recent 12 posts (likes+comments / followers)
  Demographics: requires Instagram Insights (business/creator account only)
  Refresh: token valid 60 days → store refresh_token, refresh on sync

TikTok:
  Scopes: user.info.basic, video.list
  Pull:   follower_count, following_count, video stats
  Note:   avg views = mean of last 20 videos. Demographics very limited.
  Fallback: if API restricted → prompt manual entry in Flutter

YouTube (Data API v3):
  Scopes: youtube.readonly, yt-analytics.readonly
  Pull:   subscriberCount, viewCount, videoCount
  Demographics: via YouTube Analytics API (separate auth scope)
  Quota:  10,000 units/day free → cache responses, don't call on every login

LinkedIn:
  Scopes: r_liteprofile, r_emailaddress, r_organization_social
  Pull:   follower count (company pages only — personal is restricted)
  Fallback: manual follower entry for personal profiles

Sync schedule (Railway cron):
  0 2 * * *  → run management command sync_social_stats
  Refreshes all SocialAccounts where last_synced > 7 days ago
  Recalculates creator tier after each sync

12. PAYMENT FLOWS
--------------------------------------------------------------------------------

RAZORPAY (India — deal fees):
  1. Deal reaches complete status (both parties confirm)
  2. Django calls POST /api/payments/create-deal-fee/
  3. Creates Razorpay Order with deal_fee amount in INR
  4. Returns order_id + key to Flutter
  5. Flutter opens Razorpay checkout
  6. On payment: Razorpay webhook hits /api/payments/webhook/razorpay/
  7. Django verifies signature, marks Payment.status = completed
  8. Generates invoice PDF, stores in Supabase, emails to brand

STRIPE (UAE/US/CA — deal fees):
  Same flow but using Stripe Payment Intent instead of Razorpay Order.
  Webhook: payment_intent.succeeded

BRAND SUBSCRIPTIONS (Razorpay Subscriptions / Stripe Billing):
  - Brand selects plan → Django creates subscription via gateway
  - Webhook on invoice.paid → updates Subscription.deals_included, period_end
  - Monthly reset of Subscription.deals_used via cron

IMPORTANT:
  - Payment method must be saved before Deal Room activates
  - Brand is charged only on deal completion — not at proposal acceptance
  - Deal fee is shown to brand before they confirm deal (at proposal acceptance)
  - Creator never sees or pays any fee
